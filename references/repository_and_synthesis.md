# 研究资料库与证据综合

仅在设计证据登记、编码或研究资料库时读取。

## 四层对象

1. **研究活动**：访谈、测试、问卷、日志分析等，有明确时间与样本。
2. **事实/观察**：一条可回到原始材料的记录，例如某参与者在某任务中停顿。
3. **分析推断**：对多条观察的解释，必须列支持证据和反证。
4. **建议**：基于推断和业务约束提出的行动，不伪装成用户事实。

同一条观察可以支持多个推断；一个推断也应能反向追溯到所有原始证据。不要因为一句话生动或符合先验，就把它升级为洞察。

## 最小字段

| 字段 | 要求 |
|---|---|
| `source_id` | 稳定、去标识化的来源编号 |
| `study_id` | 所属研究活动 |
| `date` | 发生或采集日期 |
| `segment/context` | 与解释有关的情境，不收集多余身份信息 |
| `observation` | 原话或行为；逐字引用需能核对 |
| `code/theme` | 可修订的编码，不等于结论 |
| `stance` | 支持、反证或未定 |
| `confidence` | 证据强度与理由 |

## 综合规则

- 先逐份熟悉材料，再编码和聚类，避免先有结论后找证据。
- 统计独立参与者或独立来源，而不是句子数量；同一转载链不算多个独立来源。
- 单一来源是待验证信号；重复出现只提高可信度，不自动证明解释正确。
- 主动保留少数观点、极端案例、沉默样本和与主主题冲突的证据。
- 版本化标签与洞察状态；不要覆盖原始证据。

资料库的价值来自可追溯和可复用，而不是文件数量。访问控制、保留期限与删除机制应在收集前确定。
